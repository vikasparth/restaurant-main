## Phase C — Backend API

| Task | Description | Status | Arch sections |
|---|---|---|---|
| **C.1** | **Segment preview endpoint** — `POST /api/v1/segments/preview`. Accepts filter definition JSON, runs it through the filter engine, returns `{count, sample_categories}`. No customer names or IDs in response. Returns `400` if count = 0 (empty segment). Requires `marketing_viewer` or `marketing_sender` role. Integration tested with real DB including consent enforcement. | ⏳ Pending | `Proposed Architecture`, `Compliance, Security, & Privacy`, `Scalability & Performance`, `Testing & QA Strategy` |
| **C.2** | **Campaign CRUD endpoints** — `POST /api/v1/campaigns`, `GET /api/v1/campaigns`, `GET /api/v1/campaigns/{id}`, `PATCH /api/v1/campaigns/{id}/cancel`. State machine transitions enforced. `created_by` set from JWT claim, never from request body. Requires `marketing_sender` role for create/cancel. | ⏳ Pending | `Proposed Architecture`, `Data Model & Schema`, `Compliance, Security, & Privacy` |
| **C.3** | **Email template endpoints** — `POST /api/v1/templates`, `GET /api/v1/templates`, `GET /api/v1/templates/{id}`. Template body validated to contain `{{unsubscribe_url}}` placeholder — reject if missing. Requires `marketing_sender` role for create. | ⏳ Pending | `Proposed Architecture`, `Data Model & Schema` |
| **C.4** | **Async campaign send worker** — `POST /api/v1/campaigns/{id}/send` accepts the send request, materialises recipient list from filter engine (consent-enforced), inserts `campaign_recipients` rows with `status=pending`, transitions campaign to `sending`, returns `202 Accepted`. Background worker (FastAPI `BackgroundTasks` or Celery — see Open Questions) processes recipients in batches of 50 via SES `SendBulkEmail`. Updates recipient status per SES response. Enforces 14 emails/second rate limit. Sets campaign to `sent` or `partially_failed` on completion. | ⏳ Pending | `Proposed Architecture`, `Data Model & Schema`, `Scalability & Performance`, `Observability & Operational Health` |
| **C.5** | **Unsubscribe endpoint** — `GET /api/v1/unsubscribe?token=<signed_token>`. Verifies signed token (HMAC, not JWT — no login required for unsubscribe). Sets `consent_marketing=false` on customer. Inserts `consent_audit_log` row with `source=unsubscribe_link`. Returns a plain HTML "You have been unsubscribed" page. | ⏳ Pending | `Compliance, Security, & Privacy`, `Data Model & Schema`, `Dependencies` |
| **C.6** | **Sentry integration (API)** — `sentry_sdk` initialisation with `beforeSend` hook that scrubs `customer_email`, `customer_name`, `customer_id`, `email`, `recipient_email`, `name` from all outgoing events. Unit test: synthetic Sentry event payload containing these fields → verify none reach the mock Sentry client. | ⏳ Pending | `Observability & Operational Health`, `Compliance, Security, & Privacy` |
