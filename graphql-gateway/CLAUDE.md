# GraphQL Gateway Rules

## Before Writing or Modifying Any Resolver

1. Read `backend/openapi.json` — find the endpoint the resolver maps to
2. Read the relevant `schemas/[feature].graphql` — verify every GraphQL field has a matching field in the OpenAPI response schema
3. Flag any mismatch before writing code — do not assume fields exist
4. Check `src/__generated__/[feature].ts` — if it references a field you are changing, find all React components that import that type before proceeding

## Where New Code Goes

| What | Where |
|---|---|
| Schema types for a new feature | `schemas/[feature].graphql` — one file per feature, never add to an existing feature's schema |
| Resolver for a new feature | `resolvers/[feature].ts` — one file per feature |
| Backend path for a new feature | `API_PATHS` in `config.ts` — never hardcode paths inside resolver functions |
| Generated TypeScript types | `src/__generated__/[feature].ts` — generated by codegen, never hand-written |
| Codegen config for a new feature | Add entry to `codegen.ts` pointing to `schemas/[feature].graphql` |

## Adding a New Feature — Checklist

1. Add `schemas/[feature].graphql` — define types against `openapi.json`
2. Add `resolvers/[feature].ts` — annotate each resolver with the `API_PATHS` key it uses
3. Add path to `API_PATHS` in `index.ts`
4. Add codegen entry in `codegen.ts`
5. Run `npm run codegen` — verify `src/__generated__/[feature].ts` is generated
6. Run `npm start` — verify server starts without errors
7. Send a test query in Apollo Sandbox — verify the resolver returns real data

## Contract Rules

- **Never rename a GraphQL field** without checking which React components import that type from `src/__generated__/` — a rename is a breaking change to React consumers
- **Never add `!` to a nullable field** — `catering_price_per_tray: Float` is nullable by design; adding `!` will cause runtime errors when the backend returns null
- **Run `npm run codegen` after every schema change** — never commit a schema change without regenerating types
- **`BACKEND_URL` comes from the environment** — never hardcode a host URL inside a resolver

## What an Agent Must Never Do

- Hand-write TypeScript types for GraphQL responses — always import from `src/__generated__/[feature].ts`
- Call backend REST endpoints directly from React components — all data fetching goes through the GraphQL gateway
- Skip reading `openapi.json` before writing a resolver — the OpenAPI spec is the contract; assumptions cause silent field mapping bugs
- Modify `src/__generated__/` files directly — they are generated; changes will be overwritten on next codegen run

## Verification Commands

Run these in order before committing any gateway change:

```bash
npm run codegen          # schema → TypeScript types
npm start                # server starts without errors
```

Then verify in Apollo Sandbox (`http://localhost:4000/`) that the changed feature returns real data.
